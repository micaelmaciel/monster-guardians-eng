# Milestone 13 — remaining 8×8 regions (net, report, mobile, DB, items, bbxxx)

Scope: every 8×8 region left after M12 (pool):

* `net` — network/system message bank `0x09D000..0x0A1108`
* `report` — post-battle / party-report messages from `0x0A12AC`
* `mobile` — tournament / Mobile Adapter GB UI `0x099B64..0x099D72`
* `mdb1`–`mdb6` — monster-DB record name fields
  (`0x0AEDE8..0x0B5728`, 6 tables, strides `0x30`/`0x34`)
* `item` — 42 item names (`0x0B5728`, `0x40`-byte records)
* `idesc` — 42 item descriptions (`0x0B720C..0x0B7900`)
* `bbxxx` — name-entry keyboard labels (`0x0BCC2C`, `0x0BCC44`)

**Result:** 766 rows — `translation/8x8_net_en.tsv` (140),
`translation/8x8_report_en.tsv` (45), `translation/8x8_mobile_en.tsv`
(42), `translation/8x8_mdb_en.tsv` (453), `translation/8x8_item_en.tsv`
(42), `translation/8x8_idesc_en.tsv` (42), `translation/8x8_bbxxx_en.tsv`
(2) — `tools/check_8x8_en.py` reports 0 errors on all seven. **All 8×8
regions are now translated.**

## net region — 140 rows (24 body templates + 61 sliced frames)

The bank is one long run of `CODE：NN−NNN⏎ ⏎` + message + `E` frame
streams; the message rows are **one-glyph-offset frames of a scroll-in
animation** (proved earlier by the `DE：33−101` / `E：33−101` / `3−101`
frame triples), so only the full-string rows are translated and every
frame row is generated by slicing the EN base at the same character
index. 24 unique message bodies (mobile-network errors: adapter not
inserted, line busy, registration, passwords, fees, maintenance…) plus
79 rows that carry the `CODE:NN-NNN⏎ ` header (half-width `:`/`-`; the
header stays 11 glyphs so header frames still align with the JP, e.g.
`CODE:33-101`). Secure-network notes and "see the manual / contact the
Mobile Support Center" boilerplate are reused across groups so the
English reads consistently. JP lines reach 53 glyphs; EN is kept
≤30 glyphs per line by paging the message over more lines (allowed:
2-line boxes page).

## report region — 45 rows (runtime-composed sentences)

Composition read from code at `0x0168E6`/`0x016900`/`0x016914` with the
append helper `0x80281EC`: `" was defeated on floor "` + floor +
`"F⏎by the party of "` + name + `"."`. Fragments that are appended
carry their leading space in EN exactly as in JP. Menu labels:
`はい` → `Yes`, `えらびなおす` → `Redo`. Two rows have no reference
(`0x0A1358`, `0x0A1366`); they are the tail fragments `" each⏎"` and
`" gained EXP."` and are translated as such (they join the level-up /
training composed sentences). Promotion/graduation trainer voice is
kept plain and warm; all composed runs were checked so that the
concatenation reads correctly (see the run-join QA note in the
milestone-12 doc for the method).

## mobile region — 42 rows (fixed-width fields, 26-glyph class rows)

One *unterminated* run split into declared fixed-width fields; rows are
`slices` between declared starts. 17 rows are stat/UI abbreviations
(`EXP`, `LV`, `DUR`, `ATP`, `DEF`, `ACT`, `INT`, `SPP`, `CAT`, `SER`,
`OBD`, `HIT`, `EVA`, `SKP`, `HP`) that are identical in EN (20
intentional EN == JP rows). Tournament class table at `0x0C36E0`: 5
`{ptr, 26}` rows, each one 26-glyph string = 17 name + 9 prize, so
`"Unlim"+"ited Class  "`, `"Lv51+ Class      "` … and `"Prize  0G"` /
`"Prize300G"` … stay exactly 26. Element names (`Fire`, `Wind`, …) and
the class headers are longer than the JP field: 6 rows need relocation
+ length-immediate patches at insertion (sites are the per-row
`movs r0,#N; str r0,[sp]` pairs before the shared draw path near
`0x8004548`, sites around `0x0044CC–0x004560`).

## Corpus fix — monster-DB walk (extractor)

The old walk started each record scan at `rec+2` and required a `0x0000`
terminator. Monster names live in a **fixed 16-byte (8-code) field**;
full names have no terminator, so they were missed and the scan leaked
into the next record, producing junk rows such as `ケベヒーモス`
(previous record's tail bytes + the name). Fix in `tools/extract_8x8.py`:

* decode up to 8 codes at `rec+0`, no terminator requirement (`kana`
  requirement kept, so binary/unused fields are not treated as names);
* `extent()` returns the walk result directly at record starts, so a
  name is never re-scanned into the binary fields after it;
* `mdb` regions keep **only record-start names**: mid-name rows come from
  name-search pointers in the `0x6C0000..0x76765D` overlay area and from
  junk-bank false references (same phenomenon as the net/report
  scroll/slice frames); the filter runs *before* the unreferenced
  sub-span drop so a junk span cannot shadow a real name (this actually
  ate `ベヒーモス` at `0x0B0708` until the order was fixed).

Corpus: 1,215 → **1,320 rows**; `mdb` rows are now 453 record names
(84 unique) and 27 junk rows were removed. All 8-glyph names are now
present (ドラゴンゴーレム, ミニミノタウロス, ミノガリズーント,
ビッググリフォン, フットグリフォン, ドラゴンザムライ,
ホワイト/ファイア/ブラック/ウインド/セカンド/ビジョンドラゴン,
スカイテンペスト, ミニガリズーント, チーフガリズント,
ドラガリズーント). The `5#` row from a junk reference is gone.

38 records hold `？？？？` (unused monster slots, e.g. `0x0B300C..`,
`0x0B4FF0..`); no code references them (verified in low code), so they
are left untranslated (nothing is ever displayed from them).

## Item descriptions — 42, relocated, ≤2×16 lines

`len`-style: pointer + length in the item record (no terminator).
Longest JP string is 32 glyphs, so the panel is **2 lines × 16**; every
EN string is 1–2 lines with explicit `⏎` and ≤16 glyphs per line
(≤32 total), keeping the JP budget. 30 of 42 are longer than the JP
length → insertion relocates all 42 strings to free space, retargets
`+0x38` and patches `+0x3C` (no truncation). The 2×16 panel geometry is
inferred from the JP budget and must be confirmed in the emulator at
first insertion (if the panel auto-wraps instead of honoring `⏎`, the
same strings still wrap to ≤2 lines at 16 glyphs).

## bbxxx — name-entry keyboard labels

`SPC` (`0x0BCC2C`) is already English. `あ` (`0x0BCC44`) is a row label
of the **kana name-entry keyboard**; English name entry is deferred
(the 16×16 kana input font and the grid redesign are a separate task),
so the label stays kana and the checker carries a documented
`KANA_ALLOW` exception (`tools/check_8x8_en.py`). Remove the exception
when the keyboard is redesigned.
